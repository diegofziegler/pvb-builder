# Paso 7: Flujos de Ingresos y/o Beneficios

## Caso de Negocio

Este paso describe los flujos de ingresos y/o beneficios esperados de la
iniciativa. Su objetivo es ayudar a construir una vision preliminar del caso de
negocio antes de lanzar un proyecto.

Los beneficios pueden expresarse como:

- Ingresos directos.
- Ahorros.
- Eficiencias operativas.
- Mejoras de experiencia.
- Impacto en usuarios, clientes, afiliados, pacientes o equipos internos.

Si no existen ingresos directos, los items deben expresar beneficios indirectos
como ahorro, eficiencia, mejora de experiencia, reduccion de tiempos,
disminucion de errores o mejora en indicadores relevantes.

## Preguntas que debe responder cada item

- Puede cuantificar ingresos o beneficios?
- Si es una mejora de UX o experiencia, a cuantos individuos afecta?
- Que usuarios, clientes, afiliados, pacientes o equipos se veran impactados?
- Que beneficio esperado se puede estimar?

## Reglas

- La lista no puede estar vacia.
- No pueden existir items repetidos.
- Cada item debe estar escrito como una oracion clara.
- Cada item debe expresar un ingreso, ahorro, eficiencia, mejora de experiencia
  u otro beneficio esperado.
- Cada item debe intentar cuantificar el beneficio o indicar que dato falta para
  poder cuantificarlo.
- Cuando el beneficio sea de experiencia o UX, debe indicar a cuantos individuos
  afecta o que poblacion se veria impactada.
- La terminologia debe ser entendible para un Jefe o Gerente.
- Debe mantener coherencia con la Vision, Target, Valor de Negocio, Necesidad,
  Solucion Propuesta, Canales e Inversion definidos previamente.

## Tarea del modelo

1. Recibir una lista de items redactados como oraciones.
2. Validar si cada item expresa un ingreso o beneficio esperado.
3. Identificar si el beneficio corresponde a ingreso, ahorro, eficiencia,
   experiencia u otro impacto.
4. Validar si el beneficio esta cuantificado o si indica que dato falta para
   cuantificarlo.
5. Validar si se identifica la poblacion impactada cuando corresponde.
6. Detectar items repetidos, ambiguos, poco cuantificables o desconectados de
   los pasos previos.
7. Proponer una version corregida para cada item que no cumpla.
